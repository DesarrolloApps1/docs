\subsection{Forma de trabajo}

Los tres repositorios siguen el mismo esquema de ramas.

\begin{itemize}
\item \textbf{Ramas fijas.} Cada repositorio tiene dos ramas permanentes. \texttt{main} guarda la versión estable, la que se puede entregar. \texttt{dev} es donde se va integrando el trabajo iterativo.
\item \textbf{Ramas de trabajo.} Para agregar algo nuevo, cada integrante crea una rama a partir de \texttt{dev} con el formato \texttt{nombre/feature}. Por ejemplo, si Joaquín trabaja en mejoras de la interfaz, la rama se llama \texttt{joa/mejoras-ui}.
\item \textbf{Pull requests.} Cuando el trabajo en la rama está listo, se abre un pull request hacia \texttt{dev}. Una vez que \texttt{dev} acumula avances estables suficientes, se abre un pull request de \texttt{dev} a \texttt{main}.
\item \textbf{Limpieza.} Después de que una rama se mergea en \texttt{dev}, se elimina, para no acumular ramas sin uso.
\item \textbf{Commits.} Chicos y frecuentes, en español y con prefijo: \texttt{feat:}, \texttt{fix:}, \texttt{docs:}, \texttt{test:}, \texttt{refactor:}.
\item \textbf{Tareas.} Un issue por requisito o pantalla, organizados en un tablero de GitHub Projects.
\end{itemize}
